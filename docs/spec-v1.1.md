## 1. 概要

保護者がスマホでDVD・Blu-rayを注文・決済できるサイトを作り、集金袋による現金の申し込みをなくします。対象は幼稚園・保育園・こども園と小学校です。写真の販売はスナップスナップ様のまま続け、視聴版（動画配信）は作りません。写真データの販売は来年度に追加する予定のため、会員・行事・注文・決済の仕組みは今回から写真と共通で使える形で作ります（12章）。

**目的**

- 集金袋の配布・回収・集計・未回収の確認をなくす（御社と学校・園の先生の作業）
- 締切前のお知らせメールで、買い忘れを減らす
- ご自宅への郵送と、締切後の注文に対応する

**会員登録を使う理由**

保護者には、最初に1回だけ会員登録をしていただきます。理由は次の3つです。

- 登録コードで確かめたお子さまの学校・園とクラスを保存し、注文のたびに入力しなくて済むようにする
- まだ注文していないご家庭にだけ、締切前のお知らせを送る
- 来年度の写真データ販売でも、同じ登録をそのまま使う

**決まったこと**

| 項目 | 内容 |
| --- | --- |
| 売るもの | 行事のDVD・Blu-ray（ディスクのみ） |
| 対象の学校・園 | 幼稚園・保育園・こども園と小学校 |
| 写真 | プリントはスナップスナップ様で継続し、新サイトから御社の写真ページへリンクする。写真データの販売は来年度に追加できる作りにする（12章） |
| 視聴版（動画配信） | 作らない |
| 使う人 | 保護者（約2,000世帯）と御社（管理画面） |

| 受け取り方 | 学校・園への一括納品、ご自宅への郵送（行事ごとに設定） |

| 補助金 | 今回の開発には使わない |

## 2. 全体の流れ

1行事あたりの流れは次のとおりです。保護者の会員登録は最初の1回だけで、登録コードの入力は年度に1回です。

1. **学校・園と行事の登録（御社）**：管理画面で、年度ごとの学年・クラスと、行事・商品・価格・締切・受け取り方法・対象の学年・クラスを登録する
2. **登録コードの配布（御社→学校・園、年1回）**：クラスごとに人数分の登録コードを発行し、カードを印刷して、学校・園からお子さま1人に1枚配っていただく
3. **会員登録（保護者・初回のみ）**：カードのQRコードを読み取り、メールアドレスとパスワードで登録する。メールで届く確認番号（6桁）を入力し、お子さまの名前を入れて完了。学年・クラスは登録コードから自動で決まる
4. **販売開始のお知らせ（自動）**：販売開始の日時に、対象の学年・クラスのお子さまにつながる会員へメールが届く
5. **注文・お支払い（保護者）**：スマホで商品・枚数・受け取り方法を選び、カード・コンビニ払い・PayPay・銀行振込で支払う
6. **締切前のお知らせ（自動）**：締切の3日前と前日に、まだ注文していない会員へメールが届く（宛先の条件は15章）
7. **締切・制作（御社）**：締切の2日後に制作本数が確定する。管理画面で本数を確認し、ディスクを制作する
8. **お届け（御社）**
   - 学校・園への納品：クラス別の仕分けリストと袋用ラベルを印刷し、袋詰めして届ける
   - 郵送：宛名データを出力して発送し、追跡番号をまとめて取り込む。発送済みにすると保護者へメールが届く
9. **締切後の注文（設定した場合）**：決めた期間だけ割増価格で受け付け、受付期限のあとにまとめて追加制作して郵送する
10. **新年度（毎年4月）**：新しい登録コードを配り、保護者がマイページで入力する（進級の手続き）。登録コードで見られるのはそのコードの年度の行事だけなので、新年度の行事を見るには新年度のコードが必要。卒園・卒業したお子さまには新しいコードが配られないため新年度の対象から外れるが、在籍していた年度の行事（卒園式など）は販売期間が終わるまで買える

行事ごとの案内チラシ（QRコード付き）は、必要に応じて管理画面から出力し、学校・園で掲示・配布していただきます。

## 3. 保護者向けの画面と機能

スマホでの操作を前提にし、会員登録後は「行事を選ぶ→枚数と受け取り方を選ぶ→支払う」の3ステップで注文できるようにします。

**ログインなしで見られるページ**

決済代行（Stripe）の審査では、ログインなしで見られるページだけで、何をいくらで売っているかがわかる必要があります（8章）。お子さまの映像を扱う行事のページはログインの奥に置き、次のページを公開します。

| 画面 | できること |
| --- | --- |
| トップ | サイトの説明、ご利用の流れ・商品と価格・よくある質問へのリンク、お問い合わせ先と受付時間、スナップスナップ様の御社の写真ページへのリンク。Stripeに登録するアドレスはこのページにする |
| ご利用の流れ | 登録コード→会員登録→注文→支払い→お届けの流れ。支払い方法ごとの払い方と期限 |
| 商品と価格 | 行事の種類ごと（運動会、発表会、卒園式・卒業式など）に、収録内容の例、収録時間の目安、ディスクとケースの仕様、再生機器の注意、標準の価格（税込）、2枚目以降の価格、締切後の価格、送料、お届けの時期、受け取り方法 |
| 見本の商品ページ | 実際の行事のページと同じ作りの見本。ジャケットは、お子さまが写らない見本の画像にする |
| よくある質問 | 登録コード、メールが届かないとき、支払い方法、キャンセル・交換など |
| 規約類 | 特定商取引法に基づく表記、利用規約、プライバシーポリシー、キャンセル・交換の規定 |
| お問い合わせ | お問い合わせ先、受付時間、フォーム |

- 行事のページを在籍のご家庭に限っている理由（お子さまの映像を扱うため、学校・園で配布した登録コードが必要）を、トップとよくある質問に書く
- ログインなしのページには、学校・園の名前、行事の日付、お子さまが写る画像を出さない
- ログインが必要なのは「注文する」から先だけにする

**ログイン後の画面**

| 画面 | できること |
| --- | --- |
| 会員登録・ログイン | メールアドレスとパスワードで登録。メールで届く確認番号（6桁）を同じ画面で入力して本人確認する（メールのリンクを開く方式にはしない）。お知らせメールの受信への同意。パスワードの再設定も確認番号で行う |
| お子さまの登録 | 登録コードを入力する（カードのQRコードから開くと入力済みになる）。1人目はお子さまの名前（ふりがな）を入力する。2人目以降のご家族は、同じ登録コードとお子さまの名前（ふりがな）が一致すると、同じお子さまにつながる。兄弟姉妹は人数分のコードを入力する |
| 販売中の行事 | つながっているお子さまが対象の行事を一覧で表示（締切日・受け取り方法つき） |
| 行事のページ | ジャケット画像、収録内容（演目・収録時間）、DVD・Blu-rayそれぞれの価格、締切、受け取り方法、お届け予定、再生機器の注意（「Blu-rayは対応機器が必要」など） |
| 注文手続き | どのお子さまの分か、商品と枚数、受け取り方法、お届け先（郵送のとき）、支払い方法を選ぶ。最終確認画面で内容を確かめて確定する（10章） |
| 注文完了 | 注文番号と内容を表示し、同じ内容をメールでも送る。コンビニ払い・銀行振込のときは払い方と期限を表示 |
| マイページ | 注文履歴と状態（7章）、締切前のキャンセル（明細ごと）、お子さまの登録と新年度の登録コードの入力、住所・メール設定の変更、領収書（PDF）の発行、退会。お子さまごとに、つながっているアカウントの数を表示する |
| お問い合わせ | 注文を選んで送れるフォーム。御社のメールに届く |

- チラシや登録コードのQRコードから来た人は、ログイン（または登録）のあと、元のページにそのまま戻る
- 会員登録の完了画面に、御社のアドレスからのメールを受け取れるようにする設定の案内を出す（5章）
- 最終確認画面では、明細ごとにお子さまの名前と学年・クラスを表示して確かめてもらう
- 文字とボタンは大きめにし、祖父母世代が注文しても迷わない画面にする

## 4. 注文のルール

商品・価格・締切・受け取り方法は、行事ごとに管理画面で設定します。「全体」の項目はすべての行事に共通のルールです。

| 項目 | ルール | 設定の単位 |
| --- | --- | --- |
| 対象の学年・クラス | 行事を見られる・注文できるお子さまを、学年またはクラスで決める。商品ごとにも絞れる（学年別のディスクなど） | 行事ごと・商品ごと |
| 商品 | 行事ごとにDVD・Blu-rayを登録。「2枚組」などの商品名も付けられる | 行事ごと |
| 価格 | 税込で表示（総額表示）。標準の価格を基本とし、ログインなしの「商品と価格」のページと一致させる。標準から外れる価格を使うときは、そのページにも載せる | 行事ごと |
| 枚数 | 1回の注文で、複数枚・複数のお子さまの分をまとめて注文できる。商品ごとに「どのお子さまの分か」を指定する | — |
| 2枚目以降の価格 | 同じ商品の2枚目以降を別の価格にできる。枚数は1回の注文の中で数える。空欄なら割引なし | 行事ごと（任意） |
| 販売期間 | 開始日時と締切日時を設定。期間外は注文できない | 行事ごと |
| 締切の延長 | 管理画面からいつでも延ばせる。延ばすと、お届け予定・支払いの期限・本数の確定日・締切前のお知らせの送信日を計算し直す。延長のお知らせを送るかどうかを選べる | 行事ごと |
| 受け取り方法 | 「学校・園への納品のみ」「郵送のみ」「選択制」から選ぶ。卒園式・卒業式は「郵送のみ」を想定 | 行事ごと |
| 送料 | 郵送のときだけ加算する全国一律の金額。初期値は全体設定で決め、行事ごとに変えられる | 全体＋行事ごと |
| お届け予定 | 「締切から約3週間後」などを、行事のページと最終確認画面に表示 | 行事ごと |
| 締切後の注文 | 受け付けるかどうか、受付期限、割増価格、お届け予定（「受付期限から約2週間後」など）を設定する。受け取りは郵送のみ。支払い方法は通常と同じ。受付期限のあとにまとめて追加制作する | 行事ごと（任意） |
| キャンセル | 締切前（締切後の注文は受付期限まで）ならマイページから取り消せる。明細ごとに取り消せ、取り消したあとの内容で合計（2枚目以降の価格と送料を含む）を計算し直して、差額を返金する。支払い待ちの注文は、注文ごとの取り消しのみ（払込票の金額を変えられないため）。締切（締切後の注文は受付期限）を過ぎると、受注生産のため取り消せない | 全体 |
| 返品（お客様のご都合） | 受注生産のため受け付けない方向で、特約の文言を弁護士に確認して決める（10章） | 全体 |
| 交換 | 再生できない・傷があるなどの不良品は、お問い合わせから受け付けて交換する。受付期限、送料の負担、学校・園で受け取った分の交換品の届け方は15章で決める | 全体 |
| 支払いの期限（コンビニ払い・銀行振込） | 注文から3日後まで。ただし締切（締切後の注文は受付期限）の2日後を超えない。期限までに入金がなければ自動で取り消す | 全体 |
| 本数の確定 | 締切の2日後（コンビニ払い・銀行振込の期限が出そろった時点）で制作本数が確定する。締切後の注文は受付期限の2日後 | 全体 |
| 行事・商品の中止 | 撮影や制作のトラブルのときは、行事ごと・商品ごとに販売を中止し、受付済みの注文をまとめて取り消して返金できる | 行事ごと・商品ごと |

## 5. お知らせメール

買い忘れを減らす中心の機能です。販売開始と締切前のメールは、行事の対象のお子さまにつながる会員だけに送ります。

| メール | 送るタイミング | 宛先 |
| --- | --- | --- |
| 確認番号（6桁） | 会員登録、パスワードの再設定、メールアドレスの変更のとき | 手続きをした人 |
| 新しいアカウントがつながったお知らせ | 登録コードで、お子さまに2人目以降のアカウントがつながったとき | そのお子さまに先につながっていた会員 |
| 販売開始のお知らせ | 行事の販売開始日時 | 対象のお子さまにつながる会員（受信に同意した人） |
| 締切3日前のお知らせ | 締切の3日前 | 対象のお子さまにつながる会員のうち、まだ注文していない人（条件は15章） |
| 締切前日のお知らせ | 締切の前日 | 同上 |
| 締切延長のお知らせ | 締切を延ばしたとき（送るかどうかは管理画面で選ぶ） | 同上 |
| 注文完了 | 注文の確定時 | 注文した人 |
| お支払いのご案内 | コンビニ払い・銀行振込を選んだとき（払込番号または振込先と、期限） | 注文した人 |
| 支払期限のお知らせ | 期限の前日 | 未入金の人。銀行振込で金額が足りないときは残額も伝える |
| 入金の確認 | コンビニ払い・銀行振込で入金されたとき | 注文した人 |
| 自動取り消し | 支払期限が過ぎたとき | 注文した人 |
| キャンセル・返金の完了 | 取り消し・返金の処理時（明細ごとの取り消しを含む） | 注文した人 |
| 行事・商品の中止のお知らせ | 中止して返金するとき | 注文した人 |
| 発送のお知らせ | 発送済みにしたとき（追跡番号つき） | 郵送で注文した人 |
| 学校・園への納品のお知らせ | 納品済みにしたとき | 学校・園で受け取る人 |
| 締切後の注文受付のお知らせ | 締切後の受付を設定した行事で、管理画面から送信（任意） | まだ注文していない会員（条件は15章） |
| 新年度の登録コード入力のお願い | 毎年4月（日付は管理画面で設定） | 全会員 |

- 文面は管理画面で編集できる。学校・園の名前・行事名・締切日時・注文内容などは自動で差し込む
- 販売開始・締切前・締切延長・締切後受付のお知らせには、配信停止のリンクと送信者の名称・住所を入れる（特定電子メール法）。配信を停止した人にも、注文・支払い・発送のメールは届く
- 受信への同意は、同意した日時と方法（どの画面で同意したか）も記録する
- 送信元は御社のドメインのアドレスにし、迷惑メールに入りにくい設定（SPF・DKIM・DMARC）を行う
- 届かなかったメール（宛先不明・受信拒否など）は会員ごとに記録し、管理画面に「メールが届いていない会員」として表示する。登録時の電話番号で連絡できる
- メールだけに頼らないよう、学校・園の連絡アプリや配布物に貼れる告知文（販売開始・締切）と注文サイトのアドレスを、管理画面から出力できる
- 送信履歴（いつ、誰に、どのメールを送り、届いたか）を管理画面で確認できる

## 6. 管理画面の機能

御社が使う画面です。パソコンでの操作を基本にし、注文の確認はスマホでもできるようにします。日々の運用（締切の延長、登録コードの再発行、年度の切り替え、メールの文面、価格・送料、支払い方法の切り替え）は、弊社に頼まなくても管理画面で完結できるようにします。

| メニュー | できること |
| --- | --- |
| ダッシュボード | 販売中の行事、今日の注文数、支払い待ちの件数、締切が近い行事、メールが届いていない会員の数 |
| 学校・園 | 登録・編集（名前、種別（園・小学校）、住所、年度ごとの学年・クラス名とクラスごとの人数、メモ） |

## 7. 注文の状態と対応

注文の状態は「支払い」と「お届け」に分けて管理します。支払いは注文ごと、お届けは明細ごとです。こうすることで、一部の明細だけの取り消しや返金、交換、来年度の写真データ（支払いと同時に提供）を同じ仕組みで扱えます。

**支払いの状態（注文ごと）**

| 状態 | 意味 | 次に起きること |
| --- | --- | --- |
| 未確定 | 決済画面に進んだが、まだ終わっていない | 支払いが済めば「支払い済み」、コンビニ払い・銀行振込なら「支払い待ち」へ。決済画面で止まったままのものは自動で消え、注文には数えない |
| 支払い待ち | コンビニ払い・銀行振込を選び、まだ入金がない | 入金で「支払い済み」へ。期限切れで「取り消し」へ（どちらも自動） |
| 支払い済み | 支払いが完了した | — |
| 一部返金 | 一部の明細を取り消して返金した | — |
| 返金済み | 全額を返金した | — |
| 取り消し | 支払いの前に取り消した（期限切れを含む） | — |

**お届けの状態（明細ごと）**

| 状態 | 意味 | 次に起きること |
| --- | --- | --- |
| 受付済み | 支払いが済み、制作を待っている | 本数の確定後、御社が「制作中」へ一括で変更 |
| 制作中 | ディスクを制作している | 学校・園への納品は「納品済み」、郵送は「発送済み」へ |
| 納品済み | 学校・園に届けた | — |
| 発送済み | 郵送した（追跡番号つき） | — |
| 取り消し | この明細を取り消した | — |
| 提供済み | データの商品を提供した（来年度の写真データで使う） | — |

**マイページでの表示**

| 表示 | 状態の組み合わせ |
| --- | --- |
| お支払い待ち（○月○日まで） | 支払い待ち |
| ご注文を受け付けました | 支払い済み＋受付済み |
| 制作中 | 支払い済み＋制作中 |
| 学校・園にお届けしました | 納品済み |
| 発送しました（追跡番号） | 発送済み |
| 取り消し | 支払いの前の取り消し |
| 取り消し（返金済み） | 明細の取り消し＋返金済み・一部返金 |

- カードとPayPayは注文時に支払いが完了するため、「支払い待ち」は通らない
- 締切後の注文も同じ流れで進む（受け取りは郵送のみ）
- 不良品の交換は、明細に「交換対応」の記録と交換品の発送日を残す（状態は変えない）
- 代理注文のうち現金（集金袋）で受けたものは、入金を確認した時点で御社が「支払い済み」にする

## 8. 決済

決済は決済代行サービスのStripeを使い、カード情報はこのサイトでは一切保存しません。Stripeのアカウントは御社名義で開設し、売上は御社の銀行口座に直接入金されます。

| 支払い方法 | 内容 | 手数料と注意点 |
| --- | --- | --- |
| クレジットカード | 主要なカードブランド。Apple Pay・Google Payも使える | 決済額の3.6%。本人認証（EMV 3-Dセキュア）に対応する（2025年3月末から国内のネット販売で原則必須。Stripeが自動で判定する）。カードの持ち主から支払いの取り消しを申し立てられた場合（チャージバック）は、1件1,500円かかる |
| コンビニ払い | ファミリーマート・ローソン・ミニストップ・セイコーマートで現金で支払う | **セブン-イレブンでは支払えない**。決済額の3.6%（最低120円）。1回120円以上30万円まで。支払いから4営業日後に入金できる残高になる。使うには事前の審査が必要（下記） |
| PayPay | スマホのPayPayアプリで支払う | 決済額の3.98%。PayPayの画面で1時間以内に承認しないと失敗する。申し込み後、PayPay側の判断で使えない場合は、ほかの支払い方法で始める |
| 銀行振込 | 会員ごとの専用の振込先（Stripeが発行）に、ネットバンキングやATMから振り込む。ATMから現金で振り込むこともできる | 決済額の1.5%。振込手数料はお客様のご負担。入金は自動で注文と照合されるため、通帳との照合は要らない。コンビニ払いのような数週間の審査を待たずに使い始められる。支払い待ちの銀行振込の注文は1会員1件まで |

- 支払い方法は管理画面でオン・オフでき、プログラムを変えずに追加・停止できる

**返金**

- カード・PayPay：締切前のキャンセルは自動で返金する（明細ごとの取り消しは差額）。それ以外は管理画面から返金する（PayPayは購入から365日以内）
- コンビニ払い・銀行振込：Stripeからお客様に、返金先の口座を入力していただくメールが自動で届き、入力後に振り込まれる。返金1件ごとに手数料250円（税別）がかかる
- 返金しても、元の決済手数料は戻らない（決済代行の規定）
- 現金（集金袋）で受けた注文の返金は、御社が直接行う

**銀行振込の金額が合わないとき**

- 足りないときは「支払い待ち」のまま、残額を支払期限のお知らせで伝える
- 多いときは、差額を管理画面からお客様に返す。照合されないまま75日たったお金は、Stripeが自動で返金を試みる

**入金**

- 売上は決済から数営業日後（コンビニ払いは4営業日後）に入金できる残高になり、設定した周期で御社の口座へ自動で振り込まれる

**決済代行の審査（コンビニ払い）**

Stripeの公開資料では、次の条件を満たしていないと、提携先やコンビニ各社の判断でコンビニ払いの申し込みを断られることがあります。サイトの公開部分（3章）は、これを満たすように作ります。

| Stripeの条件 | このサイトでの対応 |
| --- | --- |
| 注文と支払いの流れがわかる | ログインなしの「ご利用の流れ」 |
| 商品の説明と価格がそろっている | ログインなしの「商品と価格」と「見本の商品ページ」 |
| 送料などの追加費用がはっきり書かれている | 「商品と価格」と最終確認画面に表示 |
| キャンセル規定がある | ログインなしの規約類に載せる |
| 事業者名・住所（郵便番号つき）・メール・電話番号が申込内容と一致し、サイトに載っている | 特定商取引法の表記とStripeへの申込内容を、同じ表記にそろえる |
| お問い合わせの受付時間が書かれている | お問い合わせと特定商取引法の表記に載せる |
| 個人事業の場合は、事業所（店舗）の写真がある | 個人事業の場合は、会社情報に写真を載せる |
| 公開されていて、ログインやリンク切れがない | Stripeに登録するアドレスはトップにし、ログインが必要なのは「注文する」から先だけにする |

- お問い合わせの電話番号は固定電話の番号にする（過去に固定電話が条件とされた例があるため）
- **個人事業で開業から3年未満の場合は、コンビニ払いを使えない**（15章で確認）
- Stripeから問い合わせがあったときのために、見本の学校・園（架空の行事と商品）と審査用の登録コードを用意する。一般の会員には表示しない
- 審査は数週間かかる例が多い（過去の例では3〜5週間）。却下されても理由がメールで届き、直して申し込み直せる
- 審査が公開に間に合わない場合や通らなかった場合は、カード・PayPay・銀行振込で始める。現金で払いたいご家庭は、銀行振込（ATMからの現金での振込を含む）で受けられる
- それでもコンビニ払いが必要なときは、コンビニ払いだけ別の決済会社（KOMOJUなど）を追加する。審査がもう1つ増え、入金と管理が2つに分かれるため、最後の手段とする

- Vercelは、開発できる席が1つ増えるごとに20ドルかかる（閲覧だけの席は無料）。席の数は、15章の契約名義と一緒に決める

**開発用のメモ**

- Next.js（TypeScript、Node.js 24）＋Supabase（PostgreSQL・認証・行単位のアクセス制御）。Next.jsは脆弱性の修正が入った最新版を使い、Supabaseは新しい形式のAPIキー（publishable・secret）を使う
- データの保存と処理は東京で行う（Supabaseは東京リージョン、Vercelの処理も東京、Amazon SESも東京）
- 決済はStripeの決済画面（Checkout）を使い、支払いの確定・入金・返金はStripeからの通知（Webhook）で状態を更新する。銀行振込を使うには、決済画面を作るときにStripeの顧客を指定する。コンビニ払いの期限は日数で指定する
- 決済から戻った画面は、ログインしていなくても「お支払いが完了しました（詳細はメール）」を表示できるようにする（PayPayアプリから別のブラウザに戻った場合の対策）
- LINEで開かれたときは、アドレスに標準のブラウザで開く指定を付ける（動作は開発時に確認）
- 認証のメール（確認番号）は、Supabaseの標準の送信ではなくAmazon SES経由で送り、送信の上限（設定した直後は1時間30通）を引き上げる。Amazon SESは本番利用の申請を行う（申請が通るまでは、登録したアドレスにしか送れない）
- 届かなかったメールと苦情は、Amazon SESからの通知を受け取って会員ごとに記録する
- 締切前メール・支払期限切れ・本数確定は、定期実行の処理（1時間ごと）で行う
- 案内チラシ・登録コードのカード・仕分けリスト・ラベル・領収書はPDFで生成する
- 登録コードのQRコードでは、コードをアドレスの「#」以降に入れ、サーバーの記録に残らないようにする
- 本番とは別に、動作確認用の環境（Stripeのテストモード）を用意する
- 会員登録→注文→テスト決済までを通しで確かめる自動テストと、部品（ライブラリ）の更新を知らせる仕組みを入れ、更新はテストが通ってから反映する
- 稼働の監視（停止・エラーの急増・Stripeからの通知の失敗を知らせる）を設定する
- 学校・園、事業者情報、ロゴ、メールの文面、支払い方法、価格・送料などは設定として持ち、プログラムに直接書かない
